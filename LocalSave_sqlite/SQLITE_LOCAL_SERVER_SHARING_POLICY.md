# SQLite 로컬 서버와 다른 PC 공유 정책

## 지원하는 방식

- SQLite DB는 `run.py`가 실행되는 한 PC의 로컬 데이터 폴더에서 사용한다.
- 다른 PC로 이동할 때는 설정의 `공유 백업 만들기`로 생성한 `.mdpbackup`을 전달하고, 대상 PC에서 복원 미리보기와 checksum·integrity 검증 후 적용한다.
- 직접 DB 위치가 필요하면 브라우저 입력이 아니라 서버 시작 전 `MD_VIEWER_SQLITE_ROOT` 또는 `MD_VIEWER_SQLITE_PATH` 환경 옵션으로만 지정한다.
- 지정된 DB는 허용된 data root 내부의 `.sqlite`, `.sqlite3`, `.db` 파일만 가능하다.

## 지원하지 않는 방식

- OneDrive, NAS, SMB와 기타 동기화·공유 폴더의 같은 SQLite 파일을 여러 PC가 동시에 열어 쓰는 방식은 지원하지 않는다.
- 동일 data root를 사용하는 두 번째 `run.py`는 OS file lock을 획득하지 못하므로 SQLite 쓰기 서버로 시작하지 않는다.
- lock 파일을 수동 삭제해도 실행 중인 프로세스의 OS lock은 해제되지 않는다. 기존 서버를 정상 종료한 뒤 다시 실행한다.

## 실시간 다중 PC가 필요한 경우

실시간 공동 편집은 SQLite 파일 공유와 다른 구조가 필요하다. 후속 단계에서 다음 요소를 갖춘 상시 실행 호스트 서비스로 분리한다.

- 사용자 인증과 권한 분리
- TLS 연결과 비밀정보 관리
- 서버 측 쓰기 직렬화와 사용자별 충돌 정책
- 감사 로그, 백업, 장애 복구와 버전 호환 정책

현재 단계에서는 이 기능을 제공하는 것으로 오해하지 않도록 UI에 비지원 범위를 표시한다.
