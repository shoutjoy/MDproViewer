# AI Chat

ScholarAI의 문서 처리 기능과 분리된 일반 멀티턴 채팅이다.

- 설정의 `AI Chat 사용`이 켜진 경우 우측 하단에 플로팅 버튼을 표시한다.
- 플로팅 버튼은 하단 상태 표시줄보다 위에 나타나며 드래그해 이동할 수 있다. 이동한 위치는 저장되고 화면 크기 변경 시 화면 안으로 자동 보정된다.
- LM Studio 선택 시 `/api/v1/models`의 `loaded_instances`를 확인하고 현재 로드된 첫 번째 LLM을 자동 사용한다.
- AI Studio 선택 시 앱에 저장된 API Key와 선택한 Gemini 모델을 사용한다.
  - 설정을 열면 저장된 AI Studio 키로 Gemini 모델 조회를 재개하여 성공 시 빛나는 `연결됨` 상태를 표시한다. AI Studio와 imgBB 키 입력란의 눈 버튼으로 키를 일시적으로 표시하거나 다시 가릴 수 있으며, imgBB는 저장 완료와 실제 업로드 확인 완료 상태를 구분한다.
- AI Studio 모델 목록에는 공식 Gemini 3.5 Flash, Gemini 3.1 Pro Preview, Gemini 3 Flash Preview와 기존 2.5 계열을 포함한다. API 조회 결과에 추가 모델이 있으면 함께 표시한다.
- Nano Banana 2 Lite(`gemini-3.1-flash-lite-image`), Nano Banana 2(`gemini-3.1-flash-image`), Nano Banana Pro(`gemini-3-pro-image`), Nano Banana(`gemini-2.5-flash-image`)를 선택하면 채팅에서 이미지를 생성하고 결과를 IndexedDB 대화에 저장·표시하며 파일로 내려받을 수 있다.
- 생성 이미지의 `문서삽입`은 이미지를 내부 이미지 DB에 저장하고 `internal://` Markdown 이미지 주소를 현재 커서에 삽입한다. `업로드 문서삽입`은 설정에 저장된 imgBB API key로 이미지를 업로드한 뒤 반환된 HTTPS 직접 주소를 삽입한다. 두 주소는 해당 이미지 응답에 저장되어 같은 작업을 다시 실행할 때 재저장·재업로드하지 않는다.
- 응답 모드는 `즉시응답`이 기본이다. LM Studio 네이티브 `/api/v1/chat`에 `reasoning: off`, 최대 384토큰, 최대 60초를 적용한다.
- `추론` 모드는 `reasoning: on`, 최대 3072 출력 토큰, 최대 5분 대기를 적용한다.
- Gemini 2.5는 모드에 따라 `thinkingBudget: 0/4096`, Gemini 3 계열은 `thinkingLevel: low/high`를 사용한다.
- 팝업은 헤더를 드래그해 이동하고 우측 하단 모서리로 크기를 조절할 수 있으며 위치와 크기를 기억한다.
- AI 공급자·모델 선택 영역은 기본적으로 접혀 있으며 요약 행을 눌러 펼칠 수 있다.
- 팝업과 Dock의 상단 작업은 아이콘만 표시한다. 전체화면에서는 복사는 접힌 아이콘 상태를 유지하고 `새 대화·저장·배치`는 아이콘과 글자를 함께 표시한다.
- 상단의 전체 저장 아이콘은 질문·답변·체크리스트·추론·학술검색 근거를 현재 대화 제목의 Markdown(`.md`) 파일로 내려받는다.
- `배치` 메뉴에서 팝업, 앱 본문을 왼쪽으로 미는 우측 Dock, 전체화면을 선택할 수 있다.
- 우측 Dock을 왼쪽으로 680px 이상 넓히면 왼쪽에 대화 히스토리가 자동으로 나타나고, 다시 좁히면 숨겨진다. 사용자가 조절한 Dock 너비는 저장된다.
- 전체화면 왼쪽에는 대화 기록을 표시하며 대화를 선택하거나 개별 삭제할 수 있다.
- 상단의 기록 아이콘으로 팝업·Dock·전체화면에서 왼쪽 대화 기록을 직접 열고 닫을 수 있다. 좁은 팝업과 Dock에서는 기록이 왼쪽 오버레이로 표시된다.
- Dock을 왼쪽으로 넓혀 자동 표시 기준 너비에 도달하면 이전의 수동 닫힘 상태와 관계없이 히스토리가 자동으로 다시 나타난다.
- 대화방과 메시지는 IndexedDB의 `md_viewer_ai_chat` 데이터베이스에 저장하고 다음 실행 때 복원한다. 기존 단일 `localStorage` 대화는 최초 한 번 자동 이전한다.
- AI 응답은 `답변 체크리스트`와 `최종 답변`으로 분리해 표시하며 각각 복사할 수 있다.
- LM Studio 학술검색 답변은 4K 컨텍스트에서도 충분한 작성량을 확보하도록 3개 파트로 나눈다. 1/3은 근거 범위·핵심 주장, 2/3은 같은 방향 연구 비교, 3/3은 반대·조건부 결과와 종합 해석을 작성한다. 이때 체크리스트와 추론을 생성하지 않아 본문에 출력 토큰을 집중한다.
  - 세 파트는 원래의 5개 체크리스트를 `1/3=1·2번`, `2/3=3번`, `3/3=4·5번`으로 고정 배정한다. 각 파트는 대표 근거만 제한된 개수와 권장 글자 수로 요약하며, 체크 항목이 충족되면 남은 출력 토큰을 채우지 않고 종료한다. 이어쓰기는 미완료 항목만 1~3문장으로 보충하고, 기존 문단과 어휘뿐 아니라 연속 구절이 유사한 재작성도 제거한다.
  - 학술검색 본문은 대화체 존댓말 대신 `-이다/-한다/-로 나타났다/-를 시사한다`의 학술적 평서체를 사용한다. 단순 논문 나열을 피하고 핵심 주장마다 근거, 연구 간 비교·조건, 제한적인 해석이나 함의를 연결하되 확인되지 않은 인과관계는 만들지 않는다.
  - 학술검색은 화면의 응답 모드가 `추론`이어도 AI 요청을 항상 `quick`/`reasoning: off`로 전송한다. 모델이 일반 답변 필드에 `<think>`, Strategy, “The user wants”, “I need to” 같은 내부 계획을 섞어 반환해도 이를 저장·표시하지 않고 실제 한국어 본문만 남긴다. 추론만 반환된 경우에는 같은 분할 파트를 다시 생성할 수 있는 안내만 별도로 표시한다.
  - LM Studio 모델이 지정한 reasoning 값(`off` 또는 `on`)을 지원하지 않는다고 응답하면 동일 요청에서 reasoning 필드만 제거해 한 번 자동 재시도한다. 모델이 추론을 강제하더라도 추론 출력은 기존 필터에서 숨기고 최종 본문만 사용한다.
  - `다시 요약해줘`처럼 짧은 재요약 요청은 새 검색어로 보내지 않고 직전 학술검색 논문과 원 연구주제를 재사용한다. 모델 입력은 `연구 주제 + 검증 논문 요약 작업 + 현재 체크리스트 범위`로 다시 구성하며, 중복 영문 지시를 제거한 짧은 한국어 시스템 프롬프트를 사용한다. reasoning 강제 로컬 모델을 위해 학술검색 제한 시간은 최소 4분, 분할 출력 예산은 최대 2200토큰으로 확보한다.
- 출력 한도 또는 문장 중간에서 파트가 끊기면 같은 파트만 보충하고, 정상 완료되면 `다음 답변 작성`으로 다음 번호의 파트를 생성한다. 이어쓰기 요청에는 서버의 전체 이전 응답 대신 파트 번호·짧은 끝부분·축약 근거만 전달하여 새 본문 출력 공간을 확보한다.
- 이어쓰기 결과는 기존 답변 본문을 변경하지 않고 아래의 `추가 답변` 카드로 생성한다. 모델이 추론만 반환했다는 상태 문구는 답변에 섞지 않고 `안내 및 지시사항` 영역으로 분리하며, 그 아래에서 다시 이어쓰기를 실행할 수 있다.
- 추론 영역·최종 답변·추가 답변에 상태 문구가 여러 번 포함되어도 모두 제거한다. 이어쓰기 프롬프트에는 원 질문을 다시 보내지 않고 이전 답변의 끝부분과 누락 항목만 전달하며, 기존 문단과 같거나 단어 구성이 거의 같은 생성 내용은 추가 답변에 넣기 전에 제거한다.
- 이어쓰기 요청은 응답 모드 선택과 관계없이 추론을 끄며, 추가 답변에는 체크리스트와 모델의 생각/추론을 생성·표시하지 않는다. 모델이 본문 대신 Topic·Context·Task·Constraint 같은 작업 계획을 반환하면 답변에서 숨기고 다시 이어쓸 수 있도록 안내한다.
- 저자 메타데이터가 없는 검색 레코드는 `저자 미상(연도)` 형태의 인용을 만들지 않는다. 저자 표기 없이 제공 자료를 해석하거나, 귀속이 필요한 주장에서는 해당 레코드를 인용하지 않는다.
- 각 최종 답변 하단에서 답변만 복사하거나 질문·답변을 Markdown 형식으로 함께 복사한다. `문서에 넣기`는 선택 영역 대체, 커서 위치 삽입, 현재 줄의 한 줄 아래 삽입을 지원한다.
- 각 AI 답변의 `답변 지우기`는 질문과 다른 분할·추가 답변을 유지한 채 선택한 답변 카드 하나만 삭제한다. 마지막 추가 답변을 지우면 직전 답변에서 이어쓰기를 다시 실행할 수 있다.
- `문서에 넣기`와 학술검색 결과 삽입에서 `문서 맨 아래에 삽입`을 선택하면 현재 커서·선택 위치와 관계없이 문서 끝에 문단 간격을 맞춰 추가한다.
- 추론이 포함된 응답은 `추론+응답 삽입`으로 모델의 추론과 최종 답변을 별도 Markdown 제목으로 현재 문서에 삽입할 수 있다.
- `학술검색`을 켜면 AI 호출 전에 OpenAlex를 검색하고 Crossref로 초록·DOI를 보강한다. 기본 10건이며 5·10·20·30·50건 중 선택할 수 있다.
- 공개 초록 문헌이 부족하면 OpenAlex·Crossref의 서지정보 검색으로 자동 보충한다. 한국어 검색 결과가 여전히 0건이면 현재 선택된 AI가 핵심 개념을 짧은 영문 학술 검색어로 변환해 재검색한다. 초록 없는 문헌은 서지정보로 표시하되 연구 결과의 직접 근거로 사용하지 않는다.
- 학술검색 답변은 공개 초록에서 추출한 주장을 중심으로 통합하고, 같은 방향과 반대·조건부 결과를 저자-연도 인용과 함께 정리한다. 검색 결과 목록은 AI 답변보다 먼저 표시한다.
  - 한글·영문 저자의 괄호 인용에 포함된 `&`는 양쪽 공백을 갖도록 정규화한다. `(강&성, 2022)`처럼 공백 없는 기존 인용도 문서 렌더러가 수식으로 오인하지 않으므로 KaTeX의 `Misplaced &` 오류가 표시되지 않는다.
- LM Studio 학술검색은 4K 컨텍스트 모델에서도 실행되도록 상위 검색 근거를 제한된 프롬프트 예산에 맞춰 자동 축약하며, 전체 검색 결과는 화면과 문서 삽입용 데이터에 그대로 유지한다. 학술검색 AI 요청에는 이전 대화 대신 현재 질문과 검색 근거를 우선 사용한다.
- 공개 학술검색 결과 카드 하단에서 검색어·서지정보·초록을 포함한 전체 결과를 선택 영역 대체, 커서 위치, 현재 줄의 한 줄 아래 방식으로 문서에 삽입할 수 있다.
- 문서의 편집 영역 또는 미리보기에서 텍스트를 선택하고 `Ctrl+Alt+L`을 누르면 선택 내용이 AI Chat 입력창으로 이동한다.
- 입력창 하단의 `선택 가져오기` 버튼도 `Ctrl+Alt+L`과 동일하게 문서의 현재 선택 내용을 AI Chat 입력창으로 가져온다.
- 각 사용자 질문 하단의 `질문 복사`, `다시 질문`, `편집`으로 실패·시간 초과 요청을 즉시 재전송하거나 내용을 고쳐서 다시 보낼 수 있다. `질문 지우기`는 확인 후 해당 질문과 연결된 AI 답변·학술검색 근거를 함께 삭제한다.
- 모델이 API 응답으로 제공한 `reasoning_content`/`reasoning` 또는 Gemini `thought` 파트는 접을 수 있는 추론 영역에 표시한다.
- 응답 대기 중 단계 문구, 경과 시간, 애니메이션 점과 대기 상태 진행바를 표시한다. 진행바는 서버가 실제 완료율을 제공하지 않으므로 예상 완료율이 아니다.
- LM Studio 모델의 Load/Eject는 앱에서 제어하지 않고 LM Studio에서 수행한다.
- 시간 초과·중지된 사용자 질문은 화면에는 남지만 다음 요청의 대화 문맥에서는 제외한다.
